## 🤝 介绍

WakePro 是 AstrBot 的高阶唤醒插件，把「能否唤醒」拆成一套固定顺序的处理流水线。
当前实现中，流水线顺序已经写死，**不再支持通过配置调整阶梯顺序**。

固定顺序如下：

| 顺序 | 配置键名 | 一句话职责 | 说明 |
| --- | --- | --- | --- |
| 消息防抖 | `debounce` | 优先合并已有窗口内同一用户的连续消息 | 只处理已开启的窗口 |
| 阻塞判断 | `block` | 判断当前消息是否应直接拒绝唤醒 | 白名单用户可跳过 |
| 提及唤醒 | `mention` | 处理 @、引用和配置的唤醒词 | 命中后跳过后续语义判断 |
| 智能唤醒 | `wake` | 根据相关性、答疑、兴趣等信号判断是否唤醒 | 核心唤醒决策阶段 |
| JEV 唤醒 | `jev` | 结合群聊上下文判断普通消息是否在对机器人说话 | 需要单独配置 JEV 服务 |
| 指令屏蔽 | `command` | 避免把内置指令或前缀指令当成普通聊天 | 防抖续发消息会跳过本阶段 |
| 沉默检测 | `silence` | 唤醒后根据负面信号进入沉默期 | 白名单用户可跳过 |

---

### 消息防抖（debounce）

“合并输入”——如果当前用户已经处在一个已开启的防抖窗口内，那么这一步会优先尝试把新消息合并进上一条尚未输出的请求。支持配置监听时长、最多合并条数，以及参与防抖的消息类型（`normal`、`at`、`reply`、`command`）。

- 命中防抖窗口的后续消息会沿用已唤醒状态，不再重新走完整判断。
- 检测到 GIF 时不会参与合并。
- 达到最大合并条数后，会立即发起请求，不再继续监听后续消息。

### 阻塞判断（block）

“红绿灯”——如果消息里含屏蔽词、在唤醒 CD 内、或是复读 Bot 上一条消息，则直接拒绝唤醒。

- 唤醒 CD 默认 0.5 s，每人独立计时，优先级最高。
- 屏蔽复读默认开启，可防止“复读机”把 Bot 无限叫起。

### 提及唤醒（mention）

“明确呼叫优先”——处理 @Bot、引用 Bot 消息，以及配置的通用唤醒词和管理员专属唤醒词。命中后直接标记为唤醒，后续 JEV 不再重复判断。

### 智能唤醒（wake）

“大脑决策”——所有前置关卡通过后，才真正判断“这句消息值不值得回”。可叠加 6 种信号，全部独立开关、阈值可调：

1. 相关性唤醒（与 Bot 最近 5 条消息做语义相似度）
2. 答疑唤醒（检测到专业问句）
3. 兴趣唤醒（自定义关键词包）
4. 无聊唤醒（群聊低活跃）
5. 唤醒延长（被唤醒后 N 秒内持续在线）
6. 概率兜底（上面都没命中时，按固定概率随缘回）

当这一阶段判定为“需要回复”后，插件才会为该用户开启一段消息防抖监听窗口，后续连续消息再回到前面的 `debounce` 阶段进行合并。

### JEV 唤醒（jev）

JEV 步骤位于普通智能唤醒之后，仅处理没有被前置规则直接唤醒的普通群聊消息。它会把最近的群聊历史和当前候选消息发送到兼容 JEV `systemone` 协议的接口（请求包含 `model`、`state` 和 `questions`），返回的 `noul` 概率达到阈值后才标记为唤醒。

- 在插件配置的 JEV 区域填写 API Key、完整请求地址（通常以 `/v1/systemone` 结尾）和模型名，默认模型为 `jev-latest`。
- 可按需调整唤醒阈值、超时、失败重试次数和发送给 JEV 的历史消息条数。
- 本地部署的 JEV/Kev 服务（如 `http://<host>:8009/v1/systemone`）可开启“允许无 Key 请求”，API Key 留空即可。插件启动时会读取同级 `/v1/models`，所配置的模型不存在时会在日志中提示可用模型。
- **机器人昵称对准确率影响最大**：插件会合并“机器人昵称”、在 aiocqhttp(QQ) 平台自动获取的群名片/昵称、提及唤醒词和“机器人泛称”（默认“机器人/bot/AI”）发送给 JEV，并过滤 `/` 这类非名字的唤醒前缀。若平台无法自动获取，请手动填写“机器人昵称”。
- 历史消息来源默认为 `auto`：AstrBot 开启“持久化群聊消息记录”（群聊上下文感知 → 持久化群聊消息记录）时，直接读取 AstrBot 默认记忆库，重启不丢失，且包含机器人自身回复；否则使用插件内存中的记录。消息中的 @ 和引用会渲染为 `@名字`、`[回复 名字: 内容]`，时间以 `HH:MM:SS` 发送。
- 判定问题类型可选 `noul`（推荐）、`choice` 或 `both`（两种问题打包在同一次请求中取平均），也可自定义判定规则与问题。
- 本地小模型（如 kev-0.8b，高温度采样）输出的概率通常偏低且集中，默认 0.7 阈值几乎无法触发。可通过“概率校准中心/锐度”在 logit 空间重新拉开概率：以 `noul` 为例，可先设中心 `0.33`、锐度 `4`、阈值 `0.55`，再开启“输出判定详情”观察日志微调。`choice`/`both` 的原始概率整体更高，中心需相应调高。
- 开启“自适应唤醒边际”后，插件会以本群最近 JEV 原始概率的中位数作为基线，当前消息高出基线达到边际时也会唤醒，可适应不同模型和群聊的分布差异。
- “最短消息长度”可跳过过短消息，减少无意义请求。
- 请求失败、响应格式不正确或概率无效时，会跳过本次 JEV 判定，不影响其他唤醒步骤。
- JEV 只负责判断是否应该接话，实际回复仍由 AstrBot 当前配置的主模型生成。

### 指令屏蔽（command）

“防误触”——把可能跟 AstrBot 内置指令冲突的消息提前拦掉。支持三种模式：

- 屏蔽内置指令（如 /llm /tts …）
- 屏蔽前缀指令（如 !help 不再触发插件指令）
- 屏蔽前缀 LLM（如 !聊天 不再唤醒大模型）

### 沉默检测（silence）

“自我保护”——**仅在唤醒后生效**。
检测到“闭嘴、辱骂、人机”三类负面信号时，Bot 对该用户/群进入一段沉默时间，期间不再响应任何唤醒。
沉默时长 = 触发阈值 × 倍数，阈值越低“玻璃心”越重。
